# ParlayPing

ParlayPing is a social-first betting intelligence product built around a simple loop:

**Tag it. Track it. Tail what's left.**

Users tag **@ParlayPing** under a betting post. ParlayPing is designed to identify the original legs, separate what has already hit/missed from what is live or unstarted, calculate modeled probabilities, and open a live **Tail What's Left** builder for markets that are still available.

## Current build

The repository now contains both the public product experience and the first NFL backend.

### Public experience

- `index.html` / `styles.css` / `app.js` — landing page and interactive concept preview
- `tail.html` / `tail.css` / `tail.js` — live Tail What's Left page driven by encoded slip links
- `favicon.svg` — brand favicon

### Backend

- `api/analyze.js` — analyzes normalized NFL player-prop legs
- `api/lib/parlay-engine.js` — live leg state, player progress, modeled probability, and current sportsbook alternatives
- `api/parse.js` — parses post text and optional screenshots into normalized legs
- `api/lib/slip-parser.js` — deterministic text fallback plus optional OpenAI vision/structured extraction
- `api/x-worker.js` — guarded @ParlayPing mention worker
- `api/status.js` — safe configuration/readiness endpoint; never exposes secret values

### Data

The NFL engine currently reuses public snapshots generated by **The Sports Outpost**:

- NFL slate / game state
- NFL simulation distributions and current player stats
- NFL sportsbook markets and alternate lines

The risk builder only offers sportsbook alternatives actually present in the odds snapshot. It does not invent alternate lines.

## X mention flow

1. A user replies `@ParlayPing` beneath an X post.
2. The mention worker resolves the parent post and attached media.
3. The slip parser extracts explicit NFL player-prop legs.
4. The analysis engine classifies each leg as `HIT`, `MISS`, `LIVE`, `PENDING`, or `UNRESOLVED`.
5. ParlayPing calculates progress/probabilities and creates a `/tail?slip=...` continuation link.
6. The X worker formats a compact reply.
7. Posting remains disabled unless both approval and auto-reply safety gates are explicitly enabled.

## Runtime configuration

Copy the names from `.env.example` into the ParlayPing Vercel project's Environment Variables. Never commit real credentials.

Required for X dry-run ingestion:

- `X_USER_ID`
- `X_USER_ACCESS_TOKEN`
- `X_WORKER_SECRET`
- `PUBLIC_BASE_URL=https://parlayping.net`

Optional but recommended for screenshot/vision parsing:

- `OPENAI_API_KEY`
- `OPENAI_MODEL`

Safety gates:

- `X_AI_REPLY_APPROVED=false`
- `X_AUTOREPLY_ENABLED=false`

Keep both gates false during QA. `api/x-worker.js` will remain dry-run unless **both** are true.

## Mention scheduler

`.github/workflows/parlayping-x-mentions.yml` checks every five minutes. It intentionally does nothing until the GitHub repository secret `PARLAYPING_WORKER_SECRET` is configured.

The GitHub secret must match the Vercel environment variable `X_WORKER_SECRET`.
